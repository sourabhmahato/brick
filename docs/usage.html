Getting Started

Brick is designed to be dead simple. Include two files — one CSS, one JS — and start writing semantic HTML. No build step, no framework, no configuration.

CDN

The fastest way to get started. Add these two lines to your HTML <head>:

<link rel="stylesheet" href="https://unpkg.com/@sourabhmahato/brick/brick.min.css">
<script src="https://unpkg.com/@sourabhmahato/brick/brick.min.js" defer></script>

Or use jsDelivr:

<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@sourabhmahato/brick/brick.min.css">
<script src="https://cdn.jsdelivr.net/npm/@sourabhmahato/brick/brick.min.js" defer></script>

npm

Install via npm if you prefer a local copy or are using a bundler:

npm install @sourabhmahato/brick

Then import in your project:

// In your CSS or build pipeline
@import '@sourabhmahato/brick/brick.min.css';

// In your JS (if using a bundler)
import '@sourabhmahato/brick/brick.min.js';

Basic HTML Template

Here's a complete starter template:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My App</title>
  <link rel="stylesheet" href="https://unpkg.com/@sourabhmahato/brick/brick.min.css">
  <script src="https://unpkg.com/@sourabhmahato/brick/brick.min.js" defer></script>
</head>
<body>
  <main style="max-width: 40rem; margin: 0 auto; padding: 2rem;">
    <h1>Hello Brick</h1>
    <p>This paragraph is styled automatically.</p>
    <button>Click me</button>
    <button class="outline">Or me</button>
  </main>
</body>
</html>

The Semantic Approach

Brick styles native HTML elements and semantic attributes directly. You rarely need classes. Here's the philosophy:

Instead ofUse
<div class="btn btn-primary"><button>
<div class="alert alert-danger"><div role="alert" data-variant="error">
<div class="modal"><dialog>
<div class="toggle"><input type="checkbox" role="switch">
<div class="collapse"><details><summary>
<div class="spinner"><div aria-busy="true">

When classes are needed, they're minimal and meaningful:

  • .outline / .ghost — button style variants
  • .small / .large — size modifiers
  • .badge / .card — component identifiers
  • .hstack / .vstack — layout helpers

Web Components

A few interactive components are implemented as lightweight Web Components. They're registered automatically when you include the JS file:

ElementPurpose
<bk-tabs>Tabbed interface with keyboard nav and ARIA
<bk-dropdown>Dropdown menus with positioning and keyboard nav

Usage is simple — just wrap your content:

<bk-tabs>
  <div role="tablist">
    <button role="tab">Tab 1</button>
    <button role="tab">Tab 2</button>
  </div>
  <div role="tabpanel">Content 1</div>
  <div role="tabpanel">Content 2</div>
</bk-tabs>

JavaScript API

Brick exposes a minimal global API on window.bk:

Toast Notifications

// Simple text toast
bk.toast('Saved successfully!')

// With title
bk.toast('Your changes have been saved.', 'Success')

// With variant and options
bk.toast('Something went wrong.', 'Error', {
  variant: 'danger',        // 'info' | 'success' | 'warning' | 'danger'
  placement: 'top-right',   // 'top-right' | 'top-left' | 'bottom-right' | 'bottom-center' ...
  duration: 4000             // ms, 0 for persistent
})

// Custom element toast
bk.toast.el(document.querySelector('#my-template'))

// Clear all toasts
bk.toast.clear()

Events

Web components emit custom events:

// Tab change
document.querySelector('bk-tabs').addEventListener('bk-tab-change', (e) => {
  console.log(e.detail.index, e.detail.tab);
});

Dark Mode

Brick automatically respects the user's system color scheme preference via color-scheme: light dark and the light-dark() CSS function. No toggle needed — it just works.

To force a specific mode, set the color-scheme on the root:

/* Force light mode */
:root { color-scheme: light; }

/* Force dark mode */
:root { color-scheme: dark; }
